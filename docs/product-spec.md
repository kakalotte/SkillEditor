# 产品需求

本文件是 SkillForge 在 **Rust + Tauri** 实现下的产品需求说明。权威来源是主规格
`../../SkillForge_Rust_Slint_Product_and_Implementation_Plan.md`；本文只记录
**本实现实际交付了什么、以及哪些地方与主规格不同**，避免出现「文档写了但代码没做」。

## 1. 产品定位

个人经验 → 标准 **Agent Skills** 的本地优先桌面编辑器。

- 单机、离线、不需要登录。
- 面向已经知道「Skill 大概长什么样」的用户，帮他们把想法整理成规范、可被多个
  Agent 工具安装使用的目录。
- 不是 Skill 市场、不是 Agent 运行时、不代替 Agent 工具本身。

## 2. 要解决的问题

| 问题 | 本产品的做法 |
| --- | --- |
| 不知道 `SKILL.md` 的正确结构 | 表单 + 源码编辑，实时校验并给出规则链接 |
| 不知道目录放哪、怎么装 | 平台适配页列出各工具的默认路径，安装前显示差异预览 |
| 改一个字段怕丢别的内容 | 未知字段、资源文件严格保留；坏 frontmatter 可在应用内修复 |
| 装错地方 / 覆盖别人的文件 | 覆盖前自动备份；卸载只删应用写入的文件 |
| 不同工具字段不一样 | 按平台分级提示（规范 / 平台 / 建议），只提示不擅自修改 |

## 3. MVP 范围

### 做（已交付）

1. 工作区扫描与列表（搜索、刷新、修改时间、状态徽章）。
2. `SKILL.md` 的 frontmatter + 正文编辑（表单 + 源码），源码/预览双视图。
3. 校验：`SPEC-*` / `PLAT-*` / `QUAL-*` 三类共 20 条规则，
   含行号与规则文档链接。
4. 新建、保存、另存为、重命名目录外的移动（通过另存为）、删除（带确认）。
5. 导入（目录 / `SKILL.md` / `.zip`）与导出 `.zip`。
6. 六个平台 adapter：Claude Code、OpenAI Codex、OpenCode、DeepSeek Harness、
   DeepSeek Harness Desktop、通用目录。
7. 安装：差异预览 → 备份 → 落盘 → 记录清单。
8. 卸载：只删清单内文件，检测外部修改并提示。
9. 设置：工作区、主题、备份数量、外部修改检测开关；路径显示。
10. 主题：浅色 / 深色 / 跟随系统。
11. **只读 Frontmatter 规则参考**：字段类型、必填性、约束、YAML 示例、常见错误、
    平台支持、完整 `SKILL.md` 示例、正文/目录规则与 20 条校验规则；
    「必填字段」页顶部附当前文档的紧凑状态摘要。
    本阶段只提供查看，不提供字段编辑器或整份源码编辑器。

### 不做（明确排除）

- 不运行 Skill 内的任何脚本（规格 §10.2 强制要求）。
- 不联网、不上传内容、不做遥测。
- 不做富文本 Markdown 渲染（预览即「将要写入磁盘的全文」，见 `0004`）。
- 不做 Git 集成、不做 Skill 市场、不做多用户。
- 不做增量索引 / 数据库；工作区就是普通目录，`SKILL.md` 就是真相。

## 4. 核心用户流程

### 4.1 从零创建一个 Skill

1. 「技能」页点「新建 Skill」→ 编辑器页出现空文档（`draft:1`）。
2. 填 `name`、`description`；在源码视图写正文。
3. 侧栏实时显示校验结果与结构统计。
4. 点「保存」→ 名称校验通过且目录不存在时，写入
   `<工作区>/<name>/SKILL.md`，状态栏回报路径。
5. 刷新列表可看到新 Skill。

### 4.2 导入并修复一个坏 Skill

1. 「导入…」→ 选择目录 / `SKILL.md` / `.zip`。
2. 若 frontmatter 语法错误：源码视图显示**原始文本**，侧栏提示
   「frontmatter 无法解析：…修复成功前无法保存」，name/description 输入框只读。
3. 在源码视图改正 YAML → 防抖后侧栏立刻恢复可编辑，脏标记出现。
4. 点「保存」成功。

### 4.3 安装到某个平台

1. 在编辑器打开一个 `name` 合法且 frontmatter 解析成功的 Skill。
   若文档有未保存修改，先点「保存」——安装预览会拒绝脏文档，避免安装磁盘上的旧内容。
2. 切到「平台」页 → 每个平台卡片显示「当前 Skill：兼容 / N 项兼容提醒」，
   每个目标行有「安装预览」。
3. 弹出差异表：新增/更新/删除/无变化计数 + 逐文件说明；若目标已存在会提示
   「覆盖前会先创建备份」；若检测到外部修改会给出黄色警告。
   同时列出该平台的兼容提醒（`PLAT-*`）与安装时将执行的字段映射
   （例如 `when_to_use → whenToUse`）；有提醒时按钮为「仍然安装」。兼容提醒按**投影后的安装副本**重新校验，已被自动适配的字段只出现在映射区，不会同时报「会被忽略」。
4. 点「安装」→ 执行；点「取消」→ 不产生任何半成品。
5. 再次预览会显示全部「无变化」（字段映射是确定性的，不会每次都改）。

### 4.4 卸载

1. 目标行「卸载」→ 弹出确认，说明只会删除本应用写入的 N 个文件。
2. 若文件被外部修改过，额外警告「仍会删除它们」。
3. 确认后按清单删除，并清理空目录。

### 4.5 查阅 Frontmatter 规则

1. 打开任意 Skill，点工具栏「Frontmatter 规则」，或侧栏「查看全部字段与规则」。
2. 「必填字段」页顶部显示一条紧凑的当前文档状态：必填完整性、已用字段数、
   缺失的必填字段与 `description` 字符数；其他分页与搜索时不显示。
   平台列表上限只放在「平台扩展」页；frontmatter 损坏时只提示先修复。
3. 用分页查看必填字段、规范可选字段、平台扩展字段、正文与目录规则、20 条校验规则；
   每个字段显示类型、必填性、约束、YAML 示例、常见错误、支持平台与官方文档链接。
4. 输入关键词可跨字段、规则和正文规则搜索；「正文与目录」页包含完整 `SKILL.md` 示例。
5. 关闭弹窗后文档内容、未保存状态与磁盘文件均不改变。

## 5. 信息架构与界面

四个页面，左侧导航切换（页面状态由前端持有，后端不跟踪导航）：

```
┌──────────────────────────────────────────────────────────┐
│ 顶栏：SkillForge    <N 个 Skill · 工作区 …>        [刷新] │
├────────┬─────────────────────────────────────────────────┤
│ 技能   │  搜索     [新建][导入][刷新]                     │
│ 编辑器 │  ┌ 技能卡片 ────────────────────────────────┐    │
│ 平台   │  │ 名称 / 描述 / 徽章                       │    │
│ 设置   │  │ 路径 · 修改时间                          │    │
│        │  │ [打开][在文件管理器中显示]        [删除] │    │
├────────┴─────────────────────────────────────────────────┤
│ 状态栏：消息                        N 错误 N 警告 N 建议  v…│
└──────────────────────────────────────────────────────────┘
```

- **技能页**：搜索（防抖 200 ms）、新建、导入、刷新；卡片显示名称、描述、
  绝对路径、修改时间与状态徽章（`未保存` / `frontmatter 无法解析` /
  `已安装` / `安装已过期` / `目标被外部占用`）。
- **编辑器页**：左列 `SKILL.md` 卡片（name/description 表单、源码↔预览标签页、
  操作按钮与「Frontmatter 规则」入口）；表单下方有 `name` 命名提示与
  `description` 实时字符计数；右列为四张卡片——校验结果、结构统计、资源文件、
  frontmatter 字段。字段卡片显示当前字段摘要与「查看全部字段与规则」入口，
  并可打开只读指南。没有打开文档时显示空状态。
- **Frontmatter 规则指南（只读）**：宽弹窗 + 搜索 + 五个分页；展示字段、示例、
  平台支持、完整示例和校验规则。内容由核心库 `guide.rs` 与实时 adapter 能力生成，
  前端只负责渲染；不提供编辑控件。
- **平台页**：顶部显示当前项目目录与「重新检测」；每个平台卡片显示核实徽章、
  检测状态、核实日期、官方文档链接、支持字段、列表长度上限、资源目录、说明，
  以及当前 Skill 的兼容状态（未打开 / 兼容 / N 项提醒）和安装时适配数量；
  下面是该平台的每个目标行（范围徽章、路径、是否已安装、安装预览/卸载/打开目录）。
- **设置页**：通用设置（工作区、主题、备份数量、外部修改检测）与本地路径列表。

## 6. Skill 文件规范与内部模型

### 6.1 目录结构

```
<工作区>/
└── <skill-name>/
    ├── SKILL.md            # 必需
    ├── scripts/            # 可选资源目录（不执行）
    ├── references/         # 可选
    └── assets/             # 可选
```

除 `SKILL.md` 外的一切文件都视为**资源文件**，原样保留、原样复制、从不执行。

### 6.2 `SKILL.md`

```
---
name: pdf-tools
description: Extract text and tables from PDF files.
x-vendor: internal        # 未知字段：保留
---

# Steps
...
```

- `name`：必填，用于目录名与安装名。
- `description`：必填，平台会截断（Claude Code 1536 字符、OpenCode 与通用 1024、
  DeepSeek Harness 默认 500）。
- 其余规范字段：`license`、`compatibility`、`metadata`、`allowed-tools`。
- Claude Code 另有扩展字段（`when_to_use`、`allowed-tools`、`model` 等）。
- DeepSeek Harness 只读取 `whenToUse`（camelCase）、`metadata`、
  `disable-model-invocation`、`user-invocable`，其余字段会被忽略；
  `when_to_use` 会在安装副本中投影为 `whenToUse`（见 §8）。
- 编辑器内的只读指南由 `crates/skillforge-core/src/guide.rs` 提供字段、约束、
  示例与规则文本；平台支持集合与列表上限由 app 层从当前 adapter 实时组装，
  避免 UI 与核心规则出现第二份真相。

### 6.3 内部模型（`crates/skillforge-core/src/domain/`）

| 类型 | 职责 |
| --- | --- |
| `SkillId` | 工作区内的稳定标识（相对路径） |
| `SkillDocument` | frontmatter + 正文 + 解析状态 + 脏标记 |
| `Frontmatter` | YAML `Value`（真相）+ 强类型视图；见 `0002` |
| `Resource` | 资源文件清单（相对路径、类型、大小） |
| `ValidationIssue` | 规则 id、严重级别、来源、文件/行号、消息、建议、文档链接 |
| `naming` | 名称校验（不回写、不静默改写） |
| `path_safety` | 相对路径规范化、`safe_join`、越界判定 |

## 7. 校验规则

严重级别：`error`（错误）/ `warning`（警告）/ `info`（建议）。
来源与级别正交，**推荐章节缺失只报建议**。

| 规则 id | 级别 | 来源 | 说明 |
| --- | --- | --- | --- |
| `SPEC-FM-001` | 错误 | 规范 | frontmatter 无法解析（含行号）；以原始文本模式打开 |
| `SPEC-FM-002` | 错误 | 规范 | 缺少 YAML frontmatter |
| `SPEC-NAME-001` | 错误 | 规范 | 缺少必需字段 `name` |
| `SPEC-NAME-002` | 错误 | 规范 | `name` 不符合命名规范（小写字母/数字/单个连字符，1–64） |
| `SPEC-NAME-003` | 错误 | 规范 | `name` 与所在目录名不一致 |
| `SPEC-DESC-001` | 错误 | 规范 | 缺少必需字段 `description` |
| `SPEC-DESC-002` | 错误 | 规范 | `description` 超过 1024 字符 |
| `SPEC-COMP-001` | 错误 | 规范 | `compatibility` 超过 500 字符 |
| `SPEC-META-001` | 警告 | 规范 | `metadata` 不是键值映射 |
| `SPEC-RES-001` | 错误 | 规范 | 资源路径不安全（越出 Skill 根目录或含 `..`） |
| `PLAT-<ID>-FIELD` | 警告 | 平台 | 使用了该平台不认识的字段（安装后会被忽略，**不影响安装**） |
| `PLAT-<ID>-DESC` | 警告 | 平台 | `description`（含 `when_to_use` / `whenToUse`）超过该平台列表上限，会被截断 |
| `QUAL-DESC-001` | 建议 | 质量 | description 偏短，Agent 不易判断使用时机 |
| `QUAL-DESC-002` | 建议 | 质量 | description 未说明「何时使用」 |
| `QUAL-BODY-001` | 警告 | 质量 | 正文为空 |
| `QUAL-BODY-002` | 建议 | 质量 | 正文较短 |
| `QUAL-BODY-003` | 建议 | 质量 | 正文行数超过建议上限 500 行 |
| `QUAL-BODY-004` | 建议 | 质量 | 正文约 tokens 超过建议上限 5000 |
| `QUAL-STRUCT-001` | 建议 | 质量 | 正文缺少明显的步骤/章节结构（**建议，不是规范**） |
| `QUAL-STRUCT-002` | 建议 | 质量 | 正文中未发现示例 |

`<ID>` 为上大写的平台 id，例如 `PLAT-CLAUDE-CODE-FIELD`、`PLAT-CODEX-DESC`。
以 `PLAT-CLAUDE` 开头的规则链接到 Claude Code 文档，其余链接到 Agent Skills 规范。

规则常量（`services/validation_service.rs`）：
`MAX_DESCRIPTION_LEN = 1024`、`MAX_COMPATIBILITY_LEN = 500`、
`RECOMMENDED_MAX_BODY_LINES = 500`、`RECOMMENDED_MAX_BODY_TOKENS = 5000`。

**平台字段不兼容只报「警告」，不报错误**——规范本身允许扩展字段，
不同工具忽略未知字段是正常行为。

## 8. 平台适配

见 `platform-support.md` 与 `docs/decisions/0003-platform-adapters.md`。

安装采用「兼容提示 + 安全投影」两层：

- **兼容提示**：每个 adapter 对当前文档给出 `PLAT-*` 警告，按平台去重；
  平台页显示源文档的兼容状态，安装预览只显示投影后仍存在的提醒。
  兼容提醒不阻断安装，但安装本身需要用户显式确认。
- **安全投影**：只对官方文档写明等价关系的字段做顶层键重命名
  （当前仅 DeepSeek Harness 的 `when_to_use` → `whenToUse`）。
  只修改安装副本，源文件字节不变；保留注释、键顺序、未知字段、正文与换行风格；
  不删除字段，不为语义不同的字段强行造适配层。预览列出映射；清单记录实际写入内容的哈希与投影 `from` / `to`。

## 9. 提示与用户体验

- 所有提示为中文，使用工具语言（「frontmatter」「adapter」「差异预览」）。
- 破坏性操作（删除、卸载）必须二次确认，且后端强制要求 `confirm: true`。
- 安装预览必须同时展示文件差异、投影后仍存在的平台兼容提醒与将要执行的字段映射；
  有兼容提醒时确认按钮显示「仍然安装」，不能静默安装。
- 有未保存修改时拒绝安装，并提示先保存。
- Frontmatter 指南是**只读参考**：打开时不发保存命令、不改文件、不清除未保存状态；
  不提供字段编辑器、YAML 编辑器或整份源码编辑器。
- 状态栏区分信息 / 警告 / 错误三色，并统计错误、警告、建议数量。
- 未保存的修改在关闭窗口时被拦截，并通过 `skillforge://unsaved-edits`
  事件提示用户先保存。

## 11. 规格适用性

本实现技术栈为 **Rust + Tauri**。主规格中与 Tauri 冲突的条款不适用，
逐条对照见 `decisions/0006-spec-applicability.md`。

| 主规格 | 本实现 |
| --- | --- |
| §7.1 不引入 WebView | **不适用**（Tauri 的渲染层就是系统 WebView） |
| §7.1 不运行本地服务端 | 适用且已满足（无服务端、无端口） |
| §7 桌面技术架构 / §12 阶段 A 最小窗口 / §14「可运行的 Rust 桌面项目」 | 以 Tauri 等价物实现 |
| §1 / §6 / §9 / §10 / §11 / §13 | **全部适用并已遵循** |

以下是本实现自行附加的约束（非规格要求）：

| 自行约束 | 做法 | 见 |
| --- | --- | --- |
| 单一 Rust 工具链 | 手写 HTML/CSS/JS + `withGlobalTauri`，无 npm/打包器 | `0001`、`0004` |
| 无日志框架 | 诊断写 stderr | `0005` |
| 预览即所见即所存 | 预览 = 将要写入的全文 + 结构统计 | `0004` |
